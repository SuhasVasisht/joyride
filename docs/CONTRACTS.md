# Module contracts

These are the services (`ctx.services`), HTTP routes, bus change entities and event types that modules depend on. Keep them stable; extend them rather than rename.

## Identifiers

- **Session key:** `${source}:${id}`. `source` is `claude` or `codex`, and `id` is the native session or thread id. Hook events carry the raw `session` plus `agent`, so the key is `${agent}:${session}`.
- **Worker id:**
  - `${machine}:${pane_id}` when Herdr manages the worker (for example `local:w1:p2`).
  - `${machine}:pid:${pid}` for an unmanaged Claude Code process.
  - `${machine}:codex:${sessionId}` for an unmanaged Codex session.
- **Mission id:** the slug (filename without `.md` in `missions/`). The UI calls a mission an idea and a lens a group; ids, files and routes keep mission and lens.
- **Repo:** an absolute git toplevel path.
- **Worker owner:** `WorkerView.owner = {tier, task, via}`. `tier` is `crew`, `control`, `watched` or `excluded` (a session the captain started and keeps to themself: `fleet.yaml` lists it). A crew worker is matched to its Firstmate task by the Herdr pane the task's meta records (`herdr_pane_id`/`herdr_session`, else a herdr `window=<session>:<pane>`; `via: pane`), else by the `FM_TASK_ID` its hooks report (`via: env`), never by cwd. `WorkerView.crew` is the task id for crew, and `WorkerView.mission` is the session's mission, else the crew task's mission.
- **Worker helm:** `WorkerView.helm = {by, since, until, via}`, null for Firstmate's own pane and excluded sessions. `by` is `firstmate` by default, or `captain` from the captain's last steer (`steer.attributed` with `by: captain`, or a captain `reply` intent's `intent.sent`; `since`, `via`) until that turn ends plus 15 quiet minutes (`until`, null while the turn runs), or until a `hand_back` intent (`helm.released`). A worker at rest since after the steer counts as its turn's end when no hook reports one.

## Services

The shared review-server registry and lifecycle interface is documented in [review-servers.md](review-servers.md). Its `servers` service exposes `list(purpose?)`, `save(definition, creating)`, `act(id, action)`, `terminal(id, member)` and `logs(id, member)`. Bus entity `servers` invalidates its page and canvas cards. Authored definitions live in `servers/*.yaml`; placement uses `server:<id>` keys in `map/layout.yaml`; ownership and idempotency live in `.joyride/state/review-servers.json`. See that guide for exact restart survival and ownership rules.

## Knowledge queries

`knowledge.search(query)` returns `{items, total, mode, notices, offset, facets}` over ideas, authored notes, artifacts, sessions and Firstmate tasks. `KnowledgeItem` defines the common shape. Memory types, lifecycle review and delivery modes are removed; `mode` is `all`. Queries read sources without generating content or committing changes.

- `GET /api/knowledge/search?q=&types=&anchor=&state=&limit=&offset=&idea=&task=&session=&project=`
- `GET /api/knowledge/relations?entity=idea|task|artifact|session|note&id=` returns the item, its linked items and anchors.

The daemon prepares a source snapshot, refreshes it after source changes, coalesced for 120 ms, and emits `knowledge` when ready. Facets and pagination use the full snapshot. Missing or unreadable sources produce notices while the remaining results stay available.

## Intent kinds and their handlers

| kind | handler (module) | target / payload |
|---|---|---|
| `reply` | live | worker id / `{text, images?}`; Herdr `agent.prompt`. `images` are stored upload paths; refused for agents other than Claude Code and Codex. Any origin but `captain` is guarded (`src/modules/live/steer-guard.ts`): refused, with `result.refused` naming why, for crew (`fm-send.sh <task>` is its path), Firstmate's pane, excluded sessions, missing `fleet.yaml` authority, the captain's helm, sessions outside Herdr, a draft in the input box (never cleared), and images |
| `answer_prompt` | live | worker id / `{choice: allow \| allow_always \| deny}` or `{keys:[…]}`, optional `text`; reads the pane, picks the menu option. Guarded for other origins: needs `why`, takes no keys or text, needs the worker blocked, picks only an option whose own label is that choice, and re-reads the prompt before the key goes in; the result records `{prompt: {question, options}, picked, choice, why}` |
| `answer_ask` | asks | ask id / `{answer: string, mode?: done \| release}`. Captain only. Held tasks use `fm-captain-hold.sh answers --source joyride-map`, then an idempotent captain inbox wake note. Crew decisions use `fm-send.sh` with their resolve key when present. Prompts and guard approvals use the existing `reply`, `answer_prompt`, `approve` or `deny` intent. Reviews and nudges receive an ack label. An identical answer to the same ask lifecycle replays without delivery; a changed answer or close mode is refused. Each confirmed answer creates an authored note with the exact answer, scoped to the idea when linked. Secondmate holds remain read-only. Held-task answers are one line, without control characters, at most 512 bytes, matching the keyed intake's field limit; `reconcile` is refused |
| `recheck_ask` | asks | ask id / `{words?}`. Captain only. "This looks moot" on a Firstmate-owned call (a captain hold or a crew decision): files one captain inbox note (`fm-inbox.sh note`, idempotent per intent id) asking Firstmate to re-check it and close it its own way, or keep it and reply why, with `joyride-mission:` and `joyride-request:` markers. Never an answer and never `reconcile`; other asks are refused |
| `approve`, `deny` | live → guard | guard request id / `{reason?, remember?}`. The captain's only |
| `hand_back` | live | worker id; the captain's only. Logs `helm.released` and gives the helm back to Firstmate at once; a captain steer from before it never takes the helm again |
| `move_to_herdr` | live | worker id / `{force?}`; the captain's only (it ends the agent's process) |
| `exclude_session`, `include_session` | fleet | worker id, session key or absolute folder; the captain's only. Edits `fleet.yaml` (one commit; a live session is kept out by its session key and its worker id); crew can't be excluded |
| `launch_session` | live | cwd / `{agent, prompt?, label?, machine?, resume?, account?}` (`account`: a `usage.accounts` id; its folder goes into the pane as CODEX_HOME or CLAUDE_CONFIG_DIR). Alternatively `{here: {kind: idea \| group, id} \| {kind: project, title, cwd?}}` starts a new Claude Code or Codex session with current context and `workers.permission_mode`, returning the native `session` and filing it under its idea or group. An explicit `cwd` overrides the contextual repo. Codex identity is read from the new Herdr pane; an unavailable identity or filing failure returns the live worker with a warning. An idea with no repo uses the project checkout |
| `tell_note` | notes | note id / `{}`. "Save and tell Firstmate": files a captain inbox note (`firstmate.note`, `bin/fm-inbox.sh note --request-id <intent id>`) with the note's bullets, how to read it (`joyride notes …`), `joyride-mission:` (the idea's, or a task note's idea) and `joyride-request: <intent id>`. Works while Firstmate is stopped. `POST /api/notes/:id/tell` creates it |
| `tell_firstmate` | firstmate | `firstmate` / `{text, idea?}`. The New box's update or question for Firstmate (not a task request): files a captain inbox note (`bin/fm-inbox.sh note --request-id <intent id>`) asking Firstmate to act as it sees fit and answer with `fm-inbox.sh reply`, with `joyride-mission:` when an idea is given and `joyride-request: <intent id>`. Works while Firstmate is stopped. Its reply shows on the map like a task request's (`GET /api/firstmate/replies`) |
| `create_task`, `steer_task`, `start_firstmate` | firstmate | mission id or task id / `{brief, images?}` or `{text, images?}`. `create_task` files a captain inbox note (`bin/fm-inbox.sh note --request-id <intent id>`), never typing into Firstmate's pane, and works while Firstmate is stopped (the note waits for its next start; the result says `firstmate_running`); images go in the note as stored paths. The target may also be `auto` (Jev's `idea_place` over tasks in flight, open ideas and new; at 0.75 or more it sends, below it fails asking for a pick; a task in flight becomes a steer) or `new` (names the idea with `idea_naming` and commits it). The note carries `joyride-mission:` and `joyride-request: <intent id>`; `GET /api/firstmate/requests/<intent id>` reads `fm-inbox.sh receipts` and the backlog into stage `sent`, `read`, `replied` or `task`, `POST /api/firstmate/place {text, idea?, kinds?}` previews the placement (with `kinds: true`, for text that only mentions notes or lists, the same Jev call also answers `compose_kind`: task, note or list, returned as `kind {choice, p, auto}`), and `POST /api/firstmate/requests/<id>/nudge` re-announces an unread note |
| `reverify` | evidence | mission id |

## HTTP (all JSON)

The complete, generated route list is `docs/API.md` (`npx tsx scripts/gen-api-doc.mts`). Main groups:

- `/api/health`: `{ok, pid, root, code, modules, build, event_loop, refreshers, requests, slow_requests}`. This handler reads memory only. `event_loop` reports p99 and max delay in milliseconds over the current 30-second window. Each named refresher reports `age_ms` since success, `active_ms` while running and its last error; ages are null before the first success. `build` is the UI build id (a hash of `dist/ui/index.html`, also stamped into the served page as `<meta name="joyride-build">`), so an open tab notices a rebuild (`src/ui/lib/build.ts`).
- `/api/stream`: SSE carrying `change` events of the form `{entity, id?}` with a 300 ms reconnect hint. UI reads retry transient outages and keep their last successful data.
- `/api/guard/{requests, requests/:id, requests/:id/decide, requests/:id/timeout, pending, recent, rules, policy, classify}`
- `POST /api/new` takes `{request, text, context, standalone?}`. Explicit standalone intent bypasses judgment. An unresolved repo/group returns a `standalone` receipt in state `choose` with supported repos/groups and the configured model. The browser resubmits the original text/context with a new request id and `standalone: {cwd, placement: {kind: "new", title} | {kind: "group", id, title}, model: {backend, model, account?, effort?}}`. Launch receipts include worker/session, canvas landing and model/account/cwd/warnings. `GET /api/new/models` returns configured accounts and their model catalogs. `new_models` Settings fields are `routing` (Jev model override or native LLM backend), `small_job` and `standalone` (native LLM backend/model/account/effort); omitted execution roles default to `gpt-6-luna` on Codex. Existing explicit values are preserved.
- `/api/sessions` (`?keys=a,b` lists just those sessions), `/api/sessions/:key`, `/api/sessions/:key/transcript`
- `/api/missions`, `/api/missions/:id`, `/api/missions/:id/{sessions, health, state}`, `/api/missions/proposals`, `/api/missions/proposals/:id/{accept, reject}`, `/api/missions/backfill`, `/api/missions/move` (map regrouping: `{session, to: {mission} | {lens} | {new_lens}}`, `{task, to: {mission} | <id>}` or `{mission, from, to: {lens} | {new_lens}}`, one commit, returns `{commit, message}`), `/api/missions/move/undo` (`{commit}`), `GET /api/missions/hidden`, `POST /api/missions/hide` and `/unhide` (`{key}`: a session key or worker id set aside on the map until it does something new), `POST /api/missions/proposals/:id/reopen` (`{restore?}`: back to pending with the earlier decision in `history`; an accepted one gives its sessions back unless `restore` is false, and a mission it created that is left empty is archived)
- `/api/lenses`; group operations from the map, each returning `{commit, message, lens}` for `/api/missions/move/undo`: `POST /api/lenses/create` (`{title}`), `POST /api/lenses/rename` (`{lens, title}`, `{unfiled: <project key>, title}` or `{repo: <repo path>, title}`), `POST /api/lenses/delete` (`{lens}`), `POST /api/lenses/merge` (`{lens, into}`)
- `GET /api/missions/map` returns `{groups, ideas}` with authored task/session links and each idea's primary lens in `group`. `GET /api/missions/move/history` returns `{id, commit, at, summary, actor, undone}[]`. Map moves, group operations, their Undo, housekeeping Undo and anchored note writes accept optional `actor: {kind: "agent", id, via: "cli" | "mcp"}`; attribution is stored in a `Map-actor` git trailer. Hide/unhide accept the same actor, recorded in the index alongside view state; hide history has a null commit and a key for unhide, also available from agent Undo notifications. Agent map edits use the existing live change events and map/rail Undo notifications.
- `joyride map` shares the UI-importable action table in `src/shared/map-actions.ts`. The inventory, arguments and pending endpoints are in [Agent map edits](map-agent-parity.md).
- `POST /api/ideas/place` (`{dry_run?, tasks?}`), `GET /api/ideas/log?limit`, `POST /api/ideas/undo` (`{run} | {commit}`), `GET /api/ideas/pins` (`{ideas, tasks, sessions, grouped}`: what the captain's moves pin, with why)

## Firstmate primary continuity

`GET /api/firstmate/status` includes `primary` with `current` account, label, harness and model, the handoff `phase`, `lastSwitch` reason and note id, `error`, ordered account `choices` with fresh capacity, and `returnToClaude` when Claude can be offered again. `POST /api/firstmate/switch {account}` creates a `switch_firstmate` intent and uses the same serialized handoff as automatic exhaustion detection. The service exposes `switchPrimary(account)`; bus entity `firstmate` refreshes the hub and rail. A return to Claude is refused while Firstmate is working.

A managed chat keeps its editable composer and saved draft while Herdr reconnects. `WorkerView.controllable` describes current transport reachability; a false value with a pane does not mean an ended or unmanaged conversation. Sending is disabled during reconnects, failed worker reads and an unbound Firstmate conversation. Chat replies carry optional `binding {session, terminal_id?, control}`; the reply handler refuses changed sessions, terminals and supervisor ownership, and checks the native agent record before editing its input. Staged retries preserve that original binding. Transport failures offer retry after reconnect rather than a resume command. Unmanaged sessions retain their recovery controls.

Usage readings optionally carry `exhaustedNow` and `runwaySeconds` from quota-axi's `quotaSemantics.effectiveAvailability[].runway`. A failed read is distinct from exhausted capacity. Handoff context includes recent captain asks and queued messages verbatim, recent Firstmate statements and tools, open decisions, live worker actions, home summary and the outgoing pane tail. Full context is saved in `state/primary-handoff-<id>.json` under Joyride's runtime; the inbox note contains at most 12 KiB of excerpts and points to that JSON, the original transcript and the outgoing primary's handoff file. `fm-inbox.sh note --request-id` has a separate 180-second handoff deadline and must save the note before closing the outgoing pane. Retries replay the same id and saved body, with increasing backoff. The journal's `lastSwitch.attempts` and `retryAt` survive restarts; after three failures automatic handoff pauses and the hub error directs a manual retry. Startup receives that note id and the appropriate supervision protocol, and must produce matching `.lock` and `.session-start-complete` pids. No lock file is deleted or rewritten by Joyride.

## Daemon durability

The daemon exposes the internal `diagnostics` service with `refresh(name, fn)` and `snapshot()`. Background UI, session, worker, fleet, Firstmate and Herdr refreshes publish their ages there. `/api/workers` and `/api/fleet` read background snapshots. Herdr machine status adds `stale` and `last_refresh`; a failed reconcile preserves panes, discards subscriptions and backs off with jitter. Default RPC and subscription-ack deadlines are 1.5 seconds.

The independent watchdog checks the event-loop heartbeat and HTTP health. After ten seconds without progress, it writes active requests, slow requests and refreshers directly to stderr. With `JOYRIDE_SUPERVISED=1`, it kills the daemon for its supervisor or launchd to restart. Otherwise it logs and leaves the process running. `JOYRIDE_WATCHDOG_MS` changes the deadline.

`joyride up` starts a detached supervisor with a pid record in `.joyride/supervisor.pid`, guarded by a process-held lock in `.joyride/supervisor.lock`. The lock is released by the OS when the owner exits. State is in `.joyride/supervisor.json`; supervisor diagnostics go to `.joyride/supervisor.log` and daemon output goes to `.joyride/daemon.log`. The supervisor passes `JOYRIDE_SUPERVISED=1` and independently probes the owned daemon, so even a process stopped with SIGSTOP is killed after the watchdog deadline and replaced. Crashes back off from 250 ms to 30 seconds. Six exits within a minute stop recovery with an actionable log; hooks preserve this cap until an explicit `joyride up`. A minute of stable runtime resets backoff. `down` stops both processes and cancels pending retries. `restart` sends SIGUSR1 to the supervisor and replaces only the daemon, skipping crash backoff and enforcing the 750 ms shutdown deadline. `status` reports supervisor and daemon pids and recovery state.

`joyride install service` refuses before writing anything when the code, data or runtime root resolves under ~/Documents, ~/Desktop or ~/Downloads, including symlinks. It names Full Disk Access for the node binary and moving the repo as alternatives, and explains that the detached supervisor already covers crashes. It also refuses to compete with a running supervisor. For an unprotected location it writes an Interactive launchd agent with KeepAlive, RunAtLoad, a one-second throttle and logs in `.joyride/daemon.log`. Installation backs up a previous plist and records its original in `.joyride/install/service.json`; uninstall restores that predecessor or removes the authored plist. The installer records changes in `GLOBAL_CHANGES.md`. Its plist preserves the installing shell's PATH order, deduplicates directories, and appends the Node directory, ~/.local/bin, ~/.bun/bin and the standard Homebrew and system paths. Startup logs each unresolved daemon or Firstmate tool; health exposes the cached `runtime_tools` report and `joyride status` prints its missing names. These diagnostics do not prevent the daemon from serving. `down` unloads the service so KeepAlive does not undo the command; `up` bootstraps it again, and `restart` uses kickstart. A service from another checkout is refused.

Daemon identity includes code and data roots in health and `.joyride/daemon.json`. Startup refuses an occupied Joyride port and reports other listening Joyride processes. `joyride status` lists their pid, cwd and ports. Manual shutdown closes HTTP connections and has a 750 ms deadline. Manual restart checks the old process identity, waits up to 750 ms and replaces a process that did not exit.

Settings' `daemon.prevent_sleep` configuration defaults to false. `PUT /api/system/config` persists it and applies it immediately. `/api/system/status` includes `daemon.sleep_prevention`, a discriminated state (`off`, `unsupported`, `active` with helper pid, or `error` with recovery text). On macOS, the system module owns `/usr/bin/caffeinate -i -w <daemon pid>` and confirms its `PreventUserIdleSystemSleep` assertion through `/usr/bin/pmset -g assertions`. Disable and orderly shutdown signal only that child; the native `-w` lifetime releases the assertion after unexpected daemon death. No display-sleep, user-activity or AC-only assertion is requested. macOS can still sleep for a closed lid or explicit Sleep. Failures require an off/on retry and never start an automatic retry loop.
